# 广告投放分析平台 MVP PRD

## 1. Executive Summary

- **Problem Statement**: 效果广告账户在日常投放中同时面临花费波动、转化效率变化和多维结构迁移，运营/优化师需要在有限时间内从账户整体表现快速下钻到异常指标与异常原因。现有分析方式通常依赖多张分散报表手动比对，导致归因效率低、动作判断慢、复盘链路不完整。
- **Proposed Solution**: 建设一款面向广告投放运营/优化师的广告投放分析平台 MVP，围绕“整体效果 -> 异常指标 -> 异常原因”的工作流，提供总览、分维诊断和 A/B 测试预留区 3 个核心模块。平台以支付转化为核心目标，支持日/周/月视角切换、周同比和月同比对比，帮助用户快速完成账户诊断和优化决策准备。
- **Success Criteria**:
  - 平台支持 `曝光量、点击量、点击率、花费、点击均价、千次曝光成本、支付转化量、支付转化率、转化成本、支付金额、支付ROI` 11 个核心指标，且各页面口径一致率为 `100%`。
  - 用户可在 `3 次点击以内` 完成从账户总览到指定异常维度明细的下钻。
  - 总览页支持 `日 / 周 / 月` 3 个时间视角切换，并展示 `周同比` 与 `月同比`。
  - 使用模拟数据验证时，所有派生指标的公式校验通过率为 `100%`。
  - 在 MVP 测试流程中，用户可在 `5 分钟内` 完成一次“发现异常 -> 锁定维度 -> 查看原因”的完整诊断路径。

## 2. User Experience & Functionality

- **User Personas**:
  - 广告投放运营：日常负责账户监控、异常发现、预算与结构调整，需要快速判断问题来自人群、资源位还是创意。
  - 广告优化师：负责效果提升与复盘分析，需要比较不同维度的投放效率，并识别下一步优化方向。
  - 业务负责人：需要基于简洁的结果视图了解账户状态，不直接操作，但需要看到核心经营指标和波动原因。

- **User Stories**:
  - As a 广告投放运营, I want to 查看账户在日/周/月视角下的整体效果 so that 我能快速判断账户当前是否健康以及是否存在异常波动。
  - As a 广告优化师, I want to 按人群、资源位、创意拆解核心指标 so that 我能定位异常来源并判断优先处理对象。
  - As a 广告投放运营, I want to 查看异常指标对应的趋势与同比变化 so that 我能判断问题是短期波动还是结构性恶化。
  - As a 广告优化师, I want to 预留 A/B 测试分析入口 so that 后续可以验证创意或策略调整是否改善支付效率。

- **Acceptance Criteria**:
  - 故事 1 完成标准
    - 总览页默认展示账户层核心指标卡片和趋势区域。
    - 支持 `日 / 周 / 月` 视角切换。
    - 支持 `周同比` 和 `月同比` 展示。
    - 异常指标需以颜色、箭头或标签形式标识。
  - 故事 2 完成标准
    - 分维诊断首期固定支持 `人群、资源位、创意` 3 个维度。
    - 每个维度至少展示 `花费、点击率、支付转化率、转化成本、支付ROI`。
    - 用户可从总览模块点击进入某一异常指标的维度明细。
  - 故事 3 完成标准
    - 平台对每个核心指标保留统一口径定义。
    - 趋势区能清晰展示当前周期与对比周期的差异。
    - 异常原因说明支持结构化文本输出，例如“花费增长主要来自新闻信息流扩量，支付转化率低于账户均值”。
  - 故事 4 完成标准
    - MVP 页面中预留 A/B 测试区块和跳转入口。
    - 首期无需提供完整实验创建能力，但需支持展示 `Control / Test` 的核心结果对比框架。
    - A/B 测试区默认围绕创意测试设计，不覆盖自动流量分桶与实验调度。

- **Non-Goals**:
  - 不建设广告计划创建、定向配置、预算编辑、创意上传等投放执行功能。
  - 不实现自动出价、自动预算分配、自动诊断推荐引擎。
  - 不实现权限管理、组织架构管理、审批流和多角色协作。
  - 不接入真实广告平台 API、真实账户数据或实时数据流。
  - 不在 MVP 中覆盖地域、时段、设备、行业等更多分析维度。

## 3. AI System Requirements (If Applicable)

- **Tool Requirements**:
  - 本期产品不包含 AI 决策或生成式 AI 能力。
  - 首期仅需支持基于规则的异常说明与结构化展示。
  - 后续如扩展 AI 分析，可考虑接入规则引擎或大模型生成“异常总结”和“优化建议”。

- **Evaluation Strategy**:
  - 本期不对 AI 输出做评估。
  - 若后续引入 AI，总体评估应覆盖 `结论准确率、引用指标一致性、建议可执行性` 3 个维度。

## 4. Technical Specifications

- **Architecture Overview**:
  - 数据层：使用本地模拟数据文件作为账户分析数据源，核心粒度为 `日期 × 人群 × 资源位 × 创意`。
  - 指标层：基于原始字段统一计算 `CTR、CPC、CPM、支付转化率、转化成本、支付ROI` 等派生指标。
  - 展示层：前端页面由 `总览、分维诊断、A/B 测试预留区` 组成，所有页面共享同一套指标口径。
  - 交互流：
    - 用户先进入总览页查看账户整体健康度。
    - 若发现异常指标，则进入分维诊断页定位异常来源。
    - 若需要验证创意优化方向，则进入 A/B 测试区查看实验结果框架。

- **Integration Points**:
  - 数据源：`TBD`，MVP 阶段使用本地 `JSON/CSV` 模拟数据。
  - 前端技术栈：`TBD`，首期默认采用静态前端方案。
  - 后端服务：MVP 阶段不要求独立后端，数据可在前端本地读取。
  - 认证鉴权：MVP 阶段不包含登录与权限系统。

- **Security & Privacy**:
  - MVP 阶段仅使用模拟数据，不涉及真实广告主、投放账户、用户行为明细或个人敏感信息。
  - 模拟数据需避免映射到真实品牌、真实账户和真实经营结果。
  - 后续若接入真实数据，需明确数据最小化原则、权限边界、脱敏策略和审计机制。

## 5. Risks & Roadmap

- **Phased Rollout**:
  - MVP
    - 交付总览、分维诊断、A/B 测试预留区 3 个模块。
    - 使用模拟数据完成账户分析流程闭环。
    - 支持日/周/月视角与周同比、月同比。
  - v1.1
    - 增加更多分析维度，如地域、时段、设备。
    - 补充异常标签规则和诊断结论模板。
    - 完善 A/B 测试结果页，支持实验摘要与优胜方案标记。
  - v2.0
    - 评估接入真实数据源与后端服务。
    - 引入更细粒度的账户、计划、创意层级钻取。
    - 探索智能归因说明、优化建议和策略回放能力。

- **Technical Risks**:
  - 模拟数据若缺乏业务机制约束，容易导致指标波动失真，影响产品可信度。
  - 若指标口径在不同页面不一致，会直接削弱诊断结果的可解释性。
  - 没有真实 API 接入时，MVP 只能验证信息架构和分析逻辑，无法验证真实系统兼容性。
  - A/B 测试区若过早扩展为完整实验系统，会显著增加范围和实现复杂度。

## 附录：当前业务假设

- 平台面向腾讯生态下的效果广告分析场景，资源位首期抽象为信息流资源位。
- 核心经营目标为 `支付转化`，不覆盖留资、下载等其他目标。
- MVP 重点解决“效果监控与异常归因”，而非“广告投放执行”。
- 页面设计以真实业务文档风格为准，优先保证信息结构清晰、指标逻辑自洽和后续 demo 可落地。
